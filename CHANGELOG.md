It confirms SHORTS and LONGFORM as the only content types and TEST, QC, PREVIEW and APPROVAL as shared control stages, and it includes the 238-prompt catalog verbatim. No code changes. The next task is A-003.
- A-003 Architecture Map is complete. `docs/ARCHITECTURE.md` maps 16 bounded contexts and 5 cross-cutting areas, provider and internal interfaces, the production data flow, lifecycle statuses and gates. Every one of the 238 prompts is traced to one context. It lists 8 open questions and makes no code changes. The next task is A-004.
- A-004 Folder Structure is complete. It added the empty packages `core/`, `content/`, `providers/` and `pipeline/` under `src/ai_youtube_agent/`, and a `dashboard/` folder at the root (its platform is still open question Q4). It also added `tests/test_folder_structure.py` (7 tests) and updated the README layout and ARCHITECTURE section 7. There are no feature changes. The next task is A-005.
- A-005 Configuration Contract is complete. `core/config.py` loads typed, frozen settings with the `AI_YOUTUBE_AGENT_` prefix, per-environment `.env` files (development, test, production) and validation. Debug is forbidden in production, and secrets must be `SecretStr` with no default. Added the runtime dependency `pydantic-settings` (with `python-dotenv`), `.env.example`, the `.env.*` ignore rules and 14 tests. The next task is A-006.
- A-006 Feature Flags is complete. `core/flags.py` adds SHORTS_ENABLED (default on), LONGFORM_ENABLED (off), PUBLISH_ENABLED (off), TEST_REQUIRED (on), APPROVAL_REQUIRED (on) and AUTO_REPLY_ENABLED (off). They are exposed as `Settings.flags` and set with `AI_YOUTUBE_AGENT_FLAGS__<NAME>`. Publishing requires test and approval, and production always requires both. Added 14 tests, with no new dependencies. The next task is A-007.
- A-007 Logging Contract is complete. `core/log.py` writes one JSON object per record, with timestamp, severity, logger, message, correlation, session and job IDs, fields and exception. It defines five severity levels (`Severity`). `log_context` binds IDs through context variables, so they stay isolated across asyncio tasks, and `configure_logging` is idempotent. Added `Settings.log_level` (`AI_YOUTUBE_AGENT_LOG_LEVEL`, default INFO) and 16 tests, with no new dependencies. Redacting logs stays in #219. The next task is A-008.
- A-008 Error Model is complete. `core/errors.py` defines `AppError` with the categories `ApplicationError` (500), `DomainError` (422) and `ProviderError` (502, with a provider name and a retryable flag). Each error has a stable code, an internal `detail` that is never public, a safe `user_message`, a frozen `PublicError` view and `log_fields()` for structured logs. `to_public()` hides any unexpected exception behind a generic message. Added 16 tests, with no new dependencies. The next task is A-009.
- A-009 Dependency Injection is complete, with the design choices the user approved: a hand-written container, a composition root, and `create_app()`. `core/di.py` provides `Container` with singleton and transient lifetimes, `register_instance`, `override` for tests, type checks, cycle detection and thread-safe singletons, and it raises `RegistrationError` (an `ApplicationError`). `bootstrap.build_container()` is the only place that picks implementations, and so far it registers `Settings` and `FeatureFlags`. `main.create_app()` builds the container, configures logging and sets `app.state.container`. `/health` is unchanged, and `provide()` resolves dependencies in routes. Added 19 tests, with no new dependencies. The next task is A-010.
- A-010 Health Check is complete, with the design choices the user approved. `core/health.py` defines `HealthStatus` (ok, degraded, down), `CheckKind` (application, provider), `HealthCheck`, `CheckResult`, `HealthReport` and `HealthRegistry`. A failing application check makes the service `down`, and `GET /health` answers 503. A failing provider check makes it only `degraded`, and the answer stays 200. Checks run in parallel with a per-check timeout (default 2 s). A failure shows only the safe `to_public()` message, and the internal detail goes to the log. The registry is a singleton in the container, and `bootstrap` registers the application checks `settings` and `feature_flags`. Later providers add their own checks there. `GET /health` keeps `status` and `version` and adds `checks`. Two existing tests changed from comparing the exact body to checking each key. Added 19 tests, with no new dependencies. The next task is A-011.
- A-011 Audit Event Model is complete, with the design choices the user approved. `core/audit.py` defines a frozen `AuditEvent`. Each event has an id, a UTC timestamp, a dotted action name, a typed `Actor` (user, system or ai), an `EntityRef`, an `AuditResult` (success, failure or denied), the correlation, session and job IDs from `log_context`, and read-only metadata limited to JSON scalars. `AuditSink` is an append-only protocol with no update or delete. `InMemoryAuditSink` is the sink for now and rejects duplicate event ids, and a database sink will come with #029. `AuditLog.record()` builds the event, appends it and writes a structured log record. `bootstrap` registers `AuditSink` and `AuditLog` as singletons. There is no tamper-evidence hash chain, which is left to the security phase (#216–#223). Added 26 tests, with no new dependencies. The next task is A-012.
- A-012 Build Baseline is complete, and so is Phase A. The full foundation baseline on `59fcd2d` is recorded in `docs/A-012_BUILD_BASELINE.md`. `uv sync --locked`, `uv lock --check`, 132 tests (also with `-W error` and on 5 repeated runs), `ruff check`, `ruff format --check`, `uv build`, an isolated install of the wheel and a uvicorn run of `GET /health` all pass. There are no baseline failures and no infrastructure blockers, so no code changed. `PROJECT_STATE.md` now records the foundation baseline, the correct pushed checkpoint (`3ebc29c`) and the expected test count. The next task is B-013 Channel Entity.
- B-013 Channel Entity is complete, with the design choices the user approved. `content/channel.py` (context C1) defines a frozen `Channel` with a stable internal id (uuid4), a trimmed non-empty title, `YouTubeIdentifiers` and a `ChannelStatus` (pending, active, paused, disconnected, archived; new channels start pending). It has UTC `created_at` and `updated_at`, and `updated_at` can never be earlier than `created_at`. The `channel_id` is required and must be `UC` plus 22 characters, and the `@handle` is optional. `with_status()` and `rename()` return a new channel with the same id and `created_at`. A change that makes no difference returns the same object. No transition rules are enforced yet, except that an archived channel is read-only and raises `ChannelArchivedError` (a `DomainError`, 422). Persistence is left to #029. Added 34 tests, with no new dependencies. The next task is B-014.
- B-014 StrategyProfile Entity is complete, with the design choices the user approved (typed skeleton, one profile per channel, ISO/BCP-47 codes, actor guard). `content/strategy.py` (context C1) defines a frozen `StrategyProfile` with a stable id, a required `channel_id`, and one frozen value object per setting: `Market` (ISO 3166-1 alpha-2), `LanguageSettings` (primary and secondary BCP-47 tags, no repeats), `Audience`, `Niche` (name and content pillars), `Brand` (name and tone), `Cadence` (daily limits for SHORTS and LONGFORM), `Budget` (ISO 4217 currency, daily and monthly `Decimal` limits, daily not above monthly) and `Monetization` (tracked revenue sources, not guaranteed outcomes). `create` and `update` take an `Actor`, and any actor that is not a user is refused with `StrategyChangeNotAllowedError` (R-09). Every real change returns a new profile with the version increased by one, `updated_by` and a new UTC `updated_at`. Validation only checks that values are well formed; the detailed rules come with #044–#052 and cross-field validation with #053. One profile per channel is enforced by persistence (#029, #030). Added 90 tests, with no new dependencies. Tests: 256 passed. The next task is B-015 ContentItem Entity.
- B-015 ContentItem Entity is complete, with the design choices the user approved. `core/content_item.py` (context C2, which ARCHITECTURE section 7 places in `core/`) defines `ContentType` (SHORTS, LONGFORM), `ContentStatus` with the ten statuses listed in #031 (draft to failed), and a frozen `ContentItem` with a stable id, `channel_id`, `strategy_profile_id` and `strategy_version` (the strategy it was produced under), a trimmed working title, a status that starts at draft, and UTC timestamps. `with_status` and `rename` return a new item and apply no transition rules yet, which #032 will add. The entity does not read feature flags; `LONGFORM_ENABLED` stays with the gates and the pipeline. Added 39 tests, with no new dependencies. Tests: 295 passed. The next task is B-016 Artifact Entity.
- B-016 Artifact Entity is complete, with the design choices the user approved. `core/artifact.py` (context C2) defines `ArtifactKind` (video, audio, subtitles, thumbnail, metadata; all stored as files) and a frozen `Artifact` that is one immutable version: its own id (what an approval binds to), `content_item_id`, kind, a version starting at 1, an opaque storage `uri`, a lowercase `sha256`, `size_bytes` (1 or more), a `media_type` and a UTC `created_at`. `next_version` returns a new record with a new id and version + 1, keeps the old record unchanged, and refuses content with the same sha256. Unique (content_item_id, kind, version) is left to persistence (#029, #030). Added 37 tests, with no new dependencies. Tests: 332 passed. The next task is B-017 Script Entity.
- B-017 Script Entity is complete, with the design choices the user approved. `content/script.py` (context C5) defines three frozen entities related by id. `Script` is one immutable version (own id, `content_item_id`, version from 1, trimmed non-empty text, UTC `created_at`), and `next_version` returns a new record with version + 1 and refuses unchanged text. `Claim` belongs to one exact script version (`script_id`), so a new version starts with no claims. `Evidence` links a claim to a research source through an opaque `source_ref` (defined later by #055 and #069), with an optional excerpt. Adding claims or evidence never creates a new script version. Sections and duration (#064), fact-check results (#070) and diff metadata (#073) come later. Added 37 tests, with no new dependencies. Tests: 369 passed. The next task is B-018 Voice Entity.
- B-018 Voice Entity is complete, with the design choices the user approved. `content/voice.py` (context C7) defines a frozen `VoiceProfile` for one channel (provider name, provider `voice_id`, BCP-47 `language` reusing the B-014 pattern, optional `speaking_style`). Like the strategy, only a user `Actor` may create or update it (`VoiceChangeNotAllowedError`), and each real change bumps `version`. It also defines a frozen `AudioMetadata` that points to an `Artifact` of kind audio, the exact `Script` version that was voiced, and the voice profile id and version, with the provider and the duration in whole milliseconds. `AudioMetadata.create` refuses a non-audio artifact and an artifact and script from different content items. No cost is stored (left to #092 and B-025), and pronunciation is left to #087. Added 55 tests, with no new dependencies. Tests: 424 passed. The next task is B-019 Rights Entity.
- B-019 Rights Entity is complete, with the design choices the user approved. `content/rights.py` (context C6) defines `RiskLevel` (unknown, low, medium, high), `RiskResolution` (unresolved, resolved) and a frozen `RightsRecord` per asset: id, `content_item_id`, an opaque `asset_ref` (an Artifact id or an external asset), `source`, an optional `license`, the risk level (starts unknown), the resolution with `resolved_by` and `resolved_at`, and UTC timestamps. Any actor may set the risk level, but only a user may resolve a risk (`RightsResolutionNotAllowedError`). Changing the level or the licence makes the record unresolved again. Asset categories (#075), the registry (#076) and the rights gate (#038) come later. Added 41 tests, with no new dependencies. Tests: 465 passed. The next task is B-020 QC Entity.
- B-020 QC Entity is complete, with the design choices the user approved. `content/qc.py` (context C10) defines `QCStatus` (pass, warn, fail), a frozen `QCCheck` (lowercase dotted name such as `video.fps`, status, optional detail) and a frozen `QCResult` for one QC run: id, `content_item_id`, the exact `artifact_ids` checked (non-empty, no repeats, all from the same content item), one or more checks with unique names, and a UTC `created_at`. `status` is derived, not stored: fail if any check fails, otherwise warn if any warns, otherwise pass. A result is complete at creation, and a rerun makes a new result. Concrete checks (#117–#128) and the QC report (#129) come later. Added 43 tests, with no new dependencies. Tests: 508 passed. The next task is B-021 Approval Entity.
- B-021 Approval Entity is complete, with the design choices the user approved. `content/approval.py` (context C11) defines `ApprovalStatus` (pending, approved, rejected, changes_requested, invalidated, expired), a frozen `ArtifactBinding` that snapshots an artifact's id, kind, version and sha256, and a frozen `ApprovalRequest`: id, `content_item_id`, a non-empty tuple of bindings (no repeated artifact, each kind once, all from the item), a status that starts pending, `requested_by` (any `Actor`), an optional `qc_result_id` from the same item, and a UTC `created_at`. There are no decision methods yet: approve, reject and request changes (#139–#141), expiry (#142), invalidation (#035) and the approval gate (#034) come later. Added 41 tests, with no new dependencies. Tests: 549 passed. The next task is B-022 Publish Entity.
- B-022 Publish Entity is complete, with the design choices the user approved. `pipeline/publish.py` (context C12, which ARCHITECTURE section 7 places in `pipeline/`) defines `PublishStatus` (queued, in_progress, succeeded, failed), a frozen `PublishResult` (job id, 11-character YouTube video id, UTC `published_at`) and a frozen `PublishJob` with a caller-supplied `idempotency_key`, the content item, approval request and content type, status, attempts, `last_error` and result. `PublishJob.create` takes the `ApprovalRequest` and refuses one that is not approved (`PublishNotApprovedError`, R-08); the content item is taken from the approval. `start` begins an attempt from queued or failed, `fail` and `succeed` end it, and succeeded is final, so a second upload cannot be recorded (`PublishJobStateError`). Key generation (#151), the duplicate guard (#152), retry policy (#153) and the approval gate (#034) come later. Added 55 tests, with no new dependencies. Tests: 604 passed. The next task is B-023 Analytics Entity.
- B-023 Analytics Entity is complete, with the design choices the user approved. `content/analytics.py` (context C13) defines `MetricScope` (channel, video) and a frozen `MetricSnapshot`: id, scope, an opaque `subject_id`, a lowercase `source` name, a half-open UTC period (`period_start` before `period_end`), a UTC `retrieved_at` not before the period starts, and a non-empty read-only mapping from lowercase metric names to finite `Decimal` values (zero and negative allowed; a metric the source did not provide stays absent). Freshness is derived, not stored: `age_at(now)` and `is_stale(now, max_age)`. The max-age policy (#167, #168), units (#163) and the sync tasks (#159, #160) come later. Added 41 tests, with no new dependencies. Tests: 645 passed. The next task is B-024 Revenue Entity.
- B-024 Revenue Entity is complete, with the design choices the user approved. `content/revenue.py` (context C14) defines `RevenueStage` (estimated, final) and a frozen `RevenueRecord`: id, stage, `MetricScope` and `subject_id` (reused from B-023), a lowercase `revenue_type` (the B-014 monetization name pattern), a lowercase data `source`, an `amount` as a finite `Decimal` of 0 or more, an ISO 4217 `currency` (the B-014 pattern), a half-open UTC period, and a UTC `retrieved_at`. A final figure is always a separate record, and nothing converts an estimate into a final. A final record can only be read once its period has ended. Freshness is derived with `age_at` and `is_stale`. The revenue provider (#170), revenue sources (#173) and contribution margin (#179) come later. Added 37 tests, with no new dependencies. Tests: 682 passed. The next task is B-025 Cost Entity.
